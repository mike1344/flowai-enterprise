# FlowAI Enterprise — V1.2 项目执行文档包

> 状态：需求基线冻结；**未开发、未部署、未验收**。本包为通用项目执行依据，不含项目代码。
> 版本：Execution Plan 1.0 / 2026-10-31。适用范围：FlowAI Enterprise V1.2 + Industrial Service API V1.1。

## 已冻结决策
- 单仓库（monorepo）；**两个独立 FastAPI 后端服务** `flowai-api`、`industrial-api`，单个 Vue3 前端，管理后台与已发布应用使用不同路由及布局。
- 工业设备售后模拟业务：客户、产品型号、设备、故障记录、维修工单、操作记录；独立业务数据库；通过受控 REST API 集成，禁止 FlowAI 直接访问工业业务数据库。
- 四类平台角色：平台管理员、企业应用管理员、业务处理人员、普通用户。平台管理权不自动等于客户业务数据访问权。
- 多 AI 应用可创建、配置、测试、发布；独立 Web 页面；共享知识库可复用且受资源授权；索引使用最新已就绪版本，P1 支持回滚。
- 预置工具注册表、人工确认、Agent 工单闭环；外部模型 API 优先，保留本地模型适配接口；单企业部署；内置监控日志；单机 Docker Compose。
- P0 必须形成完整可运行闭环；P1 增强发布回滚、索引回滚、监控、恢复与交付。**禁止把 P1 功能写成 P0 已完成。**

## 项目启动与执行指令（适用于人工开发及各类 AI 编程工具）
> 阅读本仓库 `README.md` 和 `docs/01` 至 `docs/11`，将其视为当前已冻结需求基线，并结合已批准的 ADR 与变更记录。先审计仓库现状并输出差异和当前可执行的最小任务，不得假定代码已存在。严格按 `docs/02` 的任务依赖执行；一次只实现一个任务 ID，先报告计划、改动文件和测试方案，再实施；不扩范围、不跳过权限与审计；每次提交需附测试命令、实际结果、未完成项、风险及文档更新。开始执行 M00-01；如遇接口或业务规则歧义，停止相关任务并提出具体选项，不擅自编造规则。

## 执行纪律
- 需求与实现状态分开：文档中的接口、指标、示例均为**设计目标**。
- 每项任务完成定义（DoD）：代码 + 迁移（如有）+ 自动化测试 + 错误路径 + 文档 + 复核；只写代码不算完成。
- 跨服务不共享 ORM、数据库凭证和数据库事务；允许共享纯契约 Schema，但要版本化。
- 单机私有化部署**不等于离线模型推理或生产高可用**。
- 不将真实密钥、客户敏感信息、内部推理链或完整机密文档写入仓库或日志。


## 实时任务进度与分配（新增）

- **首选入口：`progress/进度看板.html`**：本地浏览器打开即可编辑任务状态、负责人、验收证据，自动计算总体/P0/P1/模块完成率与 Gate 放行。
- **跨工具唯一记录：`progress/任务进度.json`**：在看板导出并提交 Git；另一执行者导入继续。不要只依赖浏览器本地缓存。
- **逐项核对：`docs/12-项目进度看板与任务跟踪.md`**：29 项任务逐一验收与更新。
- **分配表：`progress/任务总表.csv`**：便于外部表格工具筛选与任务分配。
- **初始状态：0/29 已验收；M00-01 为 READY，其余 TODO。** 只有有验收证据且依赖全部完成的 DONE 计入进度。
