# 部署与运维手册（P0/P1 交付）

> 只想先跑起来？看 `00-快速开始.md`（本机实测的最短命令）。本文是完整部署、运维与安全基线。

> 适用版本：FlowAI Enterprise V1.2（P0 全量 + P1 增强）｜实测环境：Windows 11 26200 / Docker 29.8.2 / Compose v5.6.0
> 声明：本文所有命令均已在本机实测通过；生产部署需按客户环境重新验证并记录。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| Docker | ≥ 29.x，含 Compose v2（`docker compose version`） |
| 资源 | 建议 ≥ 4 vCPU / 8 GB（本机验证：16 vCPU） |
| 网络 | 首次构建需访问 PyPI / npm registry（可用 `PIP_INDEX_URL`、`NPM_REGISTRY` 构建参数切镜像源） |
| 端口 | 默认 8080（`FRONTEND_PORT` 可改），仅此端口对外 |

## 2. 一键部署

```powershell
cd F:\Y1\infra\compose
Copy-Item .env.example .env
# 编辑 .env：MYSQL_ROOT_PASSWORD / FLOWAI_DB_PASSWORD / INDUSTRIAL_DB_PASSWORD /
#            SERVICE_JWT_SECRET（≥32 字节）/ SESSION_SECRET / CSRF_SECRET / PUBLIC_BASE_URL

docker compose up -d
docker compose ps            # 期望 6 个服务 healthy，两个 *-migrate 为 Exited (0)
```

启动顺序由 compose 保证：`mysql` healthy → `flowai-migrate`/`industrial-migrate` 完成 → 两个 API → `frontend`。

## 3. 初始化数据

compose 只对外暴露前端端口（默认 8090），MySQL 不映射宿主端口，因此种子必须在容器内执行：

```powershell
cd F:\Y1\infra\compose
# 把仓库挂进一次性容器，用迁移镜像里的依赖和数据库连接串执行
docker compose run --rm -v F:/Y1:/repo -w /repo flowai-migrate   python seed/flowai_seed.py
docker compose run --rm -v F:/Y1:/repo -w /repo industrial-migrate python seed/industrial_seed.py
```

> 顺序：先 flowai、后 industrial（工业侧的 `admin` 身份映射依赖平台管理员账号已存在）。
> 若确实需要从宿主机连 MySQL，自行在 compose 里加 `ports: ["127.0.0.1:3306:3306"]`，且仅限本机开发。

两个种子脚本均**幂等**，可重复执行。默认账号：`admin / Passw0rd!2026`（首次登录后请修改）。

## 4. 健康检查

| 端点 | 期望 |
|---|---|
| `GET /health` | `{"status":"ok",...}`（liveness） |
| `GET /health/ready` | `checks.database/redis/chroma` 均为 ok（readiness；依赖不可用返回 503 + degraded） |
| `GET /api/flowai/health` | 统一信封 `code=SUCCESS` |
| `docker compose ps` | 6 个容器 healthy |

## 5. 日常运维

| 操作 | 命令 |
|---|---|
| 查看日志（结构化 JSON） | `docker compose logs -f flowai-api` |
| 查看容器健康 | `docker compose ps` |
| 重启单个服务 | `docker compose restart flowai-api` |
| 运行迁移（升级后） | `docker compose run --rm flowai-migrate` / `industrial-migrate` |
| 请求指标 | `GET /api/v1/monitoring/metrics?window_minutes=60` |
| 按 Trace 定位 | `GET /api/v1/monitoring/traces/{trace_id}` |
| 审计查询 | `GET /api/v1/monitoring/audit` |

## 6. 备份与恢复

```powershell
pwsh -File infra\backup\backup.ps1
pwsh -File infra\backup\restore-drill.ps1 -BackupDir infra\backup\out\<时间戳>
```

详见 `docs/audit/23-M08-01-验收证据.md`（实测 RTO 7.73s，RPO 依赖备份频率）。

## 7. 升级与回滚

1. 备份（见上）。
2. `docker compose build` 后 `docker compose up -d`；`*-migrate` 自动执行新增迁移。
3. 回归：`scripts/p0_acceptance.py` + `node scripts/e2e-cdp.mjs`。
4. 应用配置回滚：`POST /api/v1/applications/{id}/versions/{n}/rollback`。
5. 索引回滚：`POST /api/v1/knowledge-bases/{id}/indexes/{index_id}/activate`。

## 8. 安全基线

- `.env` 不入库（`.gitignore` 已覆盖）；模型密钥只以环境变量名引用，接口不回显。
- 会话为 HttpOnly Cookie + CSRF 双提交；`Secure` 按 `PUBLIC_BASE_URL` 是否 https 自动开启。
- 工业管理写 API 默认关闭（`ENABLE_ADMIN_WRITE_API=false`）。
- 生产必须前置 TLS（反向代理终止），并按客户要求配置证书。
