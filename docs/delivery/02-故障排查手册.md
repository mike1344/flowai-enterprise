# 故障排查手册

> 覆盖：模型不可用、工业服务超时、索引失败、数据库重启、容器构建失败（均已实测触发过至少一次）

## 1. 快速定位顺序

1. `docker compose ps` → 哪个容器 unhealthy / 重启中。
2. `GET /health/ready` → 哪个依赖 `unreachable`。
3. 结构化日志：`docker compose logs --tail=100 flowai-api | Select-String 'error|ERROR'`。
4. 有 Trace ID 时：`GET /api/v1/monitoring/traces/{trace_id}` 看审计、工具调用与执行状态。

## 2. 常见故障

| 现象 | 根因 | 处置 |
|---|---|---|
| `flowai-api` 反复重启，日志 `ModuleNotFoundError` | `requirements.txt` 缺运行依赖（本次曾缺 `httpx`） | 补依赖 → `docker compose build flowai-api && docker compose up -d flowai-api` |
| 构建失败 `No matching distribution found ... from versions: none` | 构建容器访问 PyPI 受限/抖动 | 使用镜像源构建：`docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`；前端同理 `NPM_REGISTRY` |
| `cffi`/`cryptography` 无法安装 | 基础镜像 Python 版本过新（3.14 无 cp314 linux wheel） | 运行镜像使用 `python:3.13-slim`（当前 Dockerfile 已固定） |
| 登录成功但后续请求 401 | Cookie `Secure` 在 HTTP 下被浏览器丢弃 | 确认 `PUBLIC_BASE_URL` 为 `http://...`（本地）或真正启用 HTTPS |
| 登录返回 429 `RATE_LIMITED` | 连续失败达到 `FLOWAI_LOGIN_MAX_ATTEMPTS`（默认 5） | 等待窗口（默认 300s）或重启服务清空计数；排查是否为暴力尝试 |\n| 变更请求 403「CSRF 校验失败」 | 前端未带 `X-CSRF-Token` 或刷新后未恢复 | `/auth/me` 已返回 `csrf_token`，前端 `fetchMe` 自动恢复；跨域部署需检查 CORS |
| 工业服务不可用 | 容器停止/网络断开 | Agent 返回 `FAILED`/`TIMED_OUT` 且提示「结果待核实」；恢复后用 `POST /executions/{id}/retry` 以**同一幂等键**重试，不会重复建单 |
| 工单疑似重复 409 `DUPLICATE_TICKET_CONFIRMATION_REQUIRED` | 存在未关闭的同设备/同故障候选 | 先 `POST /tickets/precheck` 获取候选与令牌；用户确认后再提交；候选变化需重新预检 |
| 索引构建失败但检索仍可用 | 失败版本置 `FAILED`，旧 active 不变 | 查 `GET /knowledge-bases/{id}/indexes`；修复后重新上传；必要时 `activate` 回旧版本 |
| 上传 PDF 报「文档无可解析文本」 | 扫描件/空白 PDF 无文本层 | 改用带文本的 PDF 或 DOCX；接口返回 `FAILED` + 原因，不会 500 |
| MySQL 重启后 API 不就绪 | 连接池失效 | `pool_pre_ping` 已启用；若持续 degraded 则 `docker compose restart flowai-api industrial-api` |
| 备份恢复后计数不一致 | 恢复到错误库或 SQL 截断 | 用 `restore-drill.ps1` 恢复到 scratch 库逐表核对；确认 `manifest.json` 时间戳 |

## 3. 故障演练记录（P0/P1）

| 场景 | 触发方式 | 期望与实测 |
|---|---|---|
| Create 工单超时 | 单测注入 `httpx.TimeoutException` | `TIMED_OUT` + 「结果待核实」，**不返回工单号**；重试复用同幂等键 ✔ |
| 索引构建失败 | 上传无效 PDF | 文档 `FAILED`，旧 active 索引不变，检索仍可用 ✔ |
| 工业服务宕机 | `docker stop industrial-api` | 入口 502/超时；FlowAI 侧 `FAILED`/`TIMED_OUT`（单测等价覆盖；compose 停机演练受执行环境限制已注明） |
| MySQL 重启 | `docker compose restart mysql` | 容器恢复 healthy；API readiness 恢复 ok（`pool_pre_ping`） |

## 4. 日志与脱敏

- 日志为单行 JSON：`ts/level/logger/message` + 可选 `trace_id/method/path/status/latency_ms`。
- 不记录请求头、请求体、令牌、密钥；审计 `detail` 经脱敏（`api_key` → `***`）。
- 保留期由 `LOG_RETENTION_DAYS`（默认 30）与部署侧日志轮转控制。
