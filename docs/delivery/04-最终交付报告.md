## 4. 已知限制（对客户透明）

1. 性能已补读路径（ACC-09）与写/模型路径基线（`docs/acceptance/V1.3-性能基线-20261101.md`、`-20261102.md`），仍非正式压测。首个基线暴露**并发不提升吞吐**（RPS 恒定 0.5～0.8、写路径 P95 6s），根因是阻塞 I/O 占住事件循环，已由 CR-008 修复并复测：模型路径 RPS ×2.7、写路径 P95 6059ms→125ms（SLO 达标）。剩余：未做长稳与多副本压测。
2. 对话已接入真实模型（DeepSeek）；DeepSeek 无 embedding 接口（实测 `/v1/embeddings` 404），V1.3 T3 已接入**本地 bge-small-zh（ONNX）**并保留 OpenAI 兼容 provider，语义改写命中由 4/10 提升到 10/10（证据 `docs/audit/31-T3-Embedding-验收证据.md`）。首次使用需下载约 95MB 模型，完全离线交付需烘进镜像。
3. 索引版本为"就绪指针 + 历史"；**向量存放在 MySQL（`document_chunk.embedding`），Chroma 容器实际未被使用**，因此「按版本隔离向量集合」无适用对象（V1.3 T2 核查结论，见 `docs/audit/30-T2-异步摄取-验收证据.md` §4）。文档摄取已改为 Celery + Redis 异步执行（上传 98ms 返回，worker 后台解析/向量/切版本）。
4. binlog 已在 compose 中开启（ROW + sync-binlog，保留 7 天），备份清单记录位点；**PITR 重放未验证**——官方 `mysql:8.4` 镜像不含 `mysqlbinlog`，全量恢复演练 0.22s 通过，重放步骤 SKIPPED（补救路径见 `docs/audit/32-T4-限流与PITR-验收证据.md` §4）。RPO 因此不可承诺。
5. ~~前端 Element Plus 全量引入（~1 MB）~~ → 已改为按需引入：JS 1057→**476 KB**（gzip 348→167 KB）、CSS 366→**155 KB**（gzip 49→21 KB），浏览器 E2E 9/9 复验通过。
6. 故障注入中「compose 停机」一项在执行环境受限（docker stop 未生效），已由单测等价覆盖并在验收报告中标注 SKIPPED。
7. 运行镜像 Python 3.13 / 本机测试 3.14，存在版本差异（已在 M06-02 证据中说明）。
