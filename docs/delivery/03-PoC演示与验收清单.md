# PoC 演示脚本与验收清单

> 目标：20 分钟内向客户演示「可创建/发布 AI 应用 → 知识库引用 → 设备故障咨询 → 人工确认 → 工业系统创建真实工单」的完整闭环。

## 1. 演示前准备（约 5 分钟）

```powershell
cd F:\Y1\infra\compose
docker compose up -d
docker compose ps                      # 6 个 healthy
python ..\..\seed\industrial_seed.py   # 合成客户/设备/故障
python ..\..\seed\flowai_seed.py       # admin、mock 模型、售后助手应用、设备知识库
```

浏览器打开 `http://127.0.0.1:8080`（或 `.env` 中 `FRONTEND_PORT`）。

## 2. 演示脚本

### 第 1 幕：平台能配（管理端，5 分钟）
1. 登录 `admin / Passw0rd!2026`。
2. 「AI 应用」→ 新建应用（名称 `现场演示`、slug `demo-live`）→ 选择模型 → 发布。
3. 「工具授权」→ 勾选 `get_device_info`、`get_device_faults`、`create_repair_ticket`。
4. 「知识库」→ 打开「设备知识库」→ 上传一个 PDF/Word → 观察状态 `READY`。
5. 检索测试输入「通信异常」→ 展示**引用来源**与「页码不可用」标注。

### 第 2 幕：业务闭环（应用端，10 分钟）
1. 打开 `/apps/service-agent`。
2. 输入：`device_id: 1 HC200 通信异常，请帮我创建工单`。
3. 展示：设备信息、历史故障、知识库引用。
4. 出现**工单草稿卡片**（强调：未确认前系统不会写入任何业务数据）。
5. 点击「确认创建」→ 返回真实工单号（如 `WO-20261101-0001`）。
6. 再发一次相同意图 → 展示**疑似重复工单**提示与二次确认（强调：防重复写入）。

### 第 3 幕：可观测与治理（5 分钟）
1. 「运行统计」→ 请求量、错误率、P95、按路由 Top10（说明口径）。
2. 「监控审计」接口或页面 → 按 Trace 展示：登录、发布、工具调用、确认、工单创建。
3. 展示模型密钥只以 `API_KEY_REF` 环境变量名存在，接口不回显。

## 3. 客户常问问题（预置答案）

| 问题 | 回答要点 |
|---|---|
| 会不会重复建单？ | 三重保障：预检查候选提示、二次确认令牌（一次性/300s）、幂等键；重试复用同一键 |
| AI 会不会乱写业务系统？ | 写操作必须服务端人工确认令牌；工具白名单 + 参数 JSON Schema；模型输出不作为授权 |
| 身份怎么保证？ | 短时签名令牌（iss/aud/sub/role/exp），工业侧再次鉴权 + 本地身份映射，撤销即时生效 |
| 知识库答案可信吗？ | 强制返回引用（文档/页码/分块），无证据明确拒答，不编造来源 |
| 私有化后模型数据出网吗？ | 默认走外部模型 API（数据会出网），可切换本地模型适配；部署说明中已提示风险 |
| 能跑在客户服务器吗？ | 单机 Docker Compose，仅暴露一个入口端口，已提供部署/备份/排障手册与实测记录 |

## 5. 已知限制（对客户透明）

1. 性能未做正式压测，P95 数值仅供开发环境参考。
2. 向量为离线哈希嵌入，语义检索能力弱于商用 Embedding；适配接口已预留。
3. 索引版本隔离基于「就绪指针」，未做按版本独立向量集合。
4. 无 binlog 增量备份（RPO 依赖备份频率）。
5. 前端以 Element Plus 全量引入，首屏体积约 1 MB，未做按需拆包。
