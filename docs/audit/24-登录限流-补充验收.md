# 补充验收：登录限流（429 RATE_LIMITED）

> 日期：2026-11-01｜背景：M02-01 交付时「登录失败限流」被标为遗留（`notes` 记为留待 M06-01），本次补齐并实测。

## 1. 实现

| 项 | 内容 |
|---|---|
| 模块 | `app/core/ratelimit.py`（进程内滑动窗口，键 = 用户名 + 客户端 IP） |
| 配置 | `FLOWAI_LOGIN_MAX_ATTEMPTS`（默认 5）、`FLOWAI_LOGIN_WINDOW_SECONDS`（默认 300） |
| 行为 | 达到阈值后直接 429（**即使口令正确也拦截**），响应含 `details.retry_after_seconds`；成功登录清零；不同用户名互不影响 |
| 契约 | 复用 `docs/04 §4` 已定义的 `429 RATE_LIMITED`，未新增错误码 |

## 2. 自动化测试（5 项，flowai 合计 119 passed）

| 用例 | 结果 |
|---|---|
| 连续 3 次（阈值 3）失败后第 4 次 → 429 `RATE_LIMITED` | ✔ |
| 达到阈值后即使口令正确也 429 | ✔ |
| 成功登录后计数清零（随后两次失败仍是 401） | ✔ |
| 其他用户名不受影响 | ✔ |
| 窗口过期后恢复可登录 | ✔ |

## 3. 现场实测（Compose 全栈，nginx 入口 8090）

```text
attempt 1..5 -> 401（口令错误）
attempt 6    -> 429（RATE_LIMITED）
```

## 4. 已知限制

- 计数在进程内存中：服务重启即清零，多副本部署不共享；生产多副本时应改为 Redis 计数。
- 仅对登录接口生效；其他写接口的限流属于 WAF/网关职责，未在应用层重复实现。
