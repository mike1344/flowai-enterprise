# M00-01 目录规划（单仓库 monorepo）

> 依据：`docs/01 §4`（规划目录）、ADR-001（单仓库/双 FastAPI/单 Vue3）、ADR-002（双库隔离）
> 状态：**规划已定，本轮不创建任何代码目录**；`M00-02` 按本文件落地骨架，`M00-03` 落地 `infra/` 与 `tests/` 基础设施。

---

## 1. 根目录裁定（D-01）

`docs/01 §4` 的示例根名为 `flowai-enterprise/`；实际仓库根是 **`F:\Y1`**，且 `README.md`、`docs/`、`progress/` 已在根。

**裁定：以 `F:\Y1` 为仓库根，不再嵌套 `flowai-enterprise/` 子目录。**

理由：
1. 现有 `docs/`、`progress/`、`README.md` 位于根，嵌套会破坏既有文档相对链接与看板路径；
2. 单仓库只保证"一个 Git 仓库"，不要求固定目录名；
3. 若未来需要固定产品名，可通过 Git 仓库名（remote）表达，而非目录层级。

该裁定仅影响物理布局，**不改变** `docs/01 §4` 的任何模块划分，故属于实施细节而非需求变更。

## 3. 命名与结构约定

| 项 | 约定 |
|---|---|
| Python 包 | 小写下划线；服务内统一 `app.` 顶层包；**禁止**跨服务 import（`industrial-api` 不得 import `flowai-api`） |
| 跨服务共享 | 仅允许 `packages/contracts/` 下的 OpenAPI/Schema（版本化），**禁止共享 ORM 模型与数据库凭证**（`docs/01 §5`） |
| 迁移 | 每服务独立 `migrations/` 与 `alembic.ini`；迁移文件前缀 `YYYYMMDD_描述.py`；禁止跨库外键 |
| 测试 | `tests/unit`、`tests/integration`、`tests/contract`、`tests/security`、`tests/e2e`；文件 `test_<模块>.py` |
| 前端 | 组件 `PascalCase.vue`，组合式函数 `useXxx.ts`，路由文件按布局分目录；**不允许**在组件内硬编码 API 地址 |
| API | 统一前缀 `/api/v1`；路径小写短横线；错误码大写下划线（`docs/04 §4`） |
| 日志/追踪 | 统一 `X-Trace-ID` 贯穿；结构化 JSON 日志；禁止打印令牌与密钥 |
| 脚本 | `.ps1` UTF-8 **BOM**；`.sh` LF + `set -euo pipefail` |

## 4. `.gitignore`（M00-01 新增，内容见仓库根文件）

覆盖：Python（`.venv/`、`__pycache__/`、`.pytest_cache/`、`*.pyc`）、Node（`node_modules/`、`dist/`、`.vite/`）、环境与密钥（`.env`、`.env.*`、`!.env.example`、`*.pem`、`*.key`）、数据与运行产物（`data/`、`*.sqlite3`、`logs/`、`playwright-report/`、`test-results/`）、IDE/OS（`.vscode/`、`.idea/`、`Thumbs.db`、`.DS_Store`）。

**硬规则**：真实 `.env`、模型 API Key、服务签名密钥**永不入库**；`.env.example` 只含变量名与占位值（`docs/08 §2`）。

## 7. M00-02 启动时的最小验收清单（由本规划派生）

1. `services/flowai-api` 与 `services/industrial-api` 各自 `.venv` 可创建、依赖可安装（验证 R-01）。
2. 两服务分别 `GET /health` 返回 `{"status":"ok"}`（含服务名与版本），可独立启动。
3. `frontend` 用 **npm** 安装并 `npm run dev` 起在 5173，页面可访问。
4. OpenAI 风格统一响应体与 `X-Trace-ID` 中间件在两端骨架内生效（`docs/04 §1`）。
5. `.env.example` 变量名与本文件 §5.2 一致（值留空/占位）。
6. 三端启动命令、依赖版本、健康检查输出写入 `docs/audit/` 证据文件。
