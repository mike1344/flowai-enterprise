## 2. 行为规范（ADR-009）

- `params_digest` = SHA-256(规范化业务字段 JSON)：键排序、空白折叠、`null`/缺省等价、priority 大写。
- `candidate_set_digest` = SHA-256(排序后的 `ticket_no:status`)。
- 重复判定（docs/03 §4）：同设备 + 同 `fault_id` 或同规范化 `fault_code`；两者都缺失时按规范化标题；候选状态仅 `PENDING/IN_PROGRESS/REOPENED`。
- 令牌 300s、一次性、绑定 `caller_scope + params_digest + candidate_set_digest`；参数或候选变化 → 重新预检。
- 幂等：同键同请求 → 返回**原响应**（含原 `ticket_no`）；同键不同内容 → 409 `IDEMPOTENCY_KEY_CONFLICT`；处理中 → 409 `IDEMPOTENCY_IN_PROGRESS`。

## 4. 事务与恢复

- 幂等记录与工单、`CREATE` 审计在**同一事务**提交：异常整单回滚，不会残留 `PROCESSING`（重试可继续）。
- 令牌消费在同一事务内；回滚后令牌仍可再用，避免"确认被吞"。
- `purge_expired()` 提供过期记录清理入口（M06 定时任务调用）。
