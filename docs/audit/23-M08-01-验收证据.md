## 3. RTO / RPO 记录（实测，非承诺）

| 指标 | 实测值 | 口径说明 |
|---|---|---|
| **RTO（恢复耗时）** | **7.73 秒** | 从备份目录恢复到 scratch 库并完成计数核对（数据量：两库合计 ~430 KB，单机 Docker） |
| 备份耗时 | 1.13 秒 | mysqldump + chroma 数据复制 |
| **RPO（数据丢失窗口）** | **取决于备份频率**：本次演练备份后无写入，实际丢失 = 0；生产建议 ≤24h（每日备份）+ 关键写入前手动备份 | 未做 WAL/binlog 增量，属已知限制 |

> 以上为开发机单机实测，**不构成生产 SLA**；生产需按数据量重新测量并配置 binlog 增量备份。

## 4. 升级/回滚演练

- 迁移链重放：SQLite 与 MySQL 均执行 `upgrade head → downgrade base → upgrade head` 通过（M00-03 起持续验证）。

- 索引版本回滚：见 M07-02（`/knowledge-bases/{id}/indexes/{id}/activate`）。

## 5. 已知限制

3. 恢复脚本在 scratch 库执行，生产恢复需人工切换连接串，属受控运维步骤。
