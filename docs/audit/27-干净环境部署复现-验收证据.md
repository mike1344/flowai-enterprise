## 4. 本轮发现并修复的缺陷

### 4.1 种子缺少平台管理员身份映射（功能缺陷，已修）

- 现象：管理员登录后触发 Agent 读设备，工业侧返回 `403`，执行结果为 `FAILED / 工业服务拒绝业务授权`。
- 根因：`flowai-api` 用 `current.user.username`（种子账号为 `admin`）作为服务令牌主体（`sessions.py:145`），而 `industrial-api` 按 `service_identity_binding.external_user_id` 精确匹配（`app/core/identity.py:64-72`）；`seed/industrial_seed.py` 只映射了 `flowai-user-admin-001` 等合成主体，**没有 `admin`**。空库部署时必然 403。
- 修复：`seed/industrial_seed.py` 增加 `admin → SERVICE_ADMIN` 绑定（注释说明依赖关系）。
- 验证：修复前探针返回 `FAILED`；插入绑定后同一探针返回 `WAITING_CONFIRMATION` 且带草稿与引用；全量复跑 P0 19/19、Agent 20/20。

### 4.2 部署手册的种子步骤与实际编排不符（文档缺陷，已修）

- 现象：手册 §3 让用户在宿主用 `127.0.0.1:3306` 连 MySQL 跑种子，但 compose 只发布 `8090`（`docker compose config` 仅一个 `published: "8090"`），宿主根本连不上。
- 修复：`docs/delivery/01-部署与运维手册.md` §3 改为「容器内执行」，并说明顺序（先 flowai 后 industrial）与「确需宿主直连则自行加 ports，仅限本地开发」；`docs/delivery/04-最终交付报告.md` §6 复现步骤同步更正（含 `agent_task_suite.py` 与 19/19 口径）。
