# 08 Docker Compose 私有化部署与交付

## 1. 单机部署拓扑
- 容器：reverse-proxy/frontend、flowai-api、flowai-worker、industrial-api、mysql、redis、chromadb。
- 单主机 Docker Compose；同一内部网络；仅代理入口对外；数据库和向量库仅内部访问；持久卷承载 MySQL、ChromaDB、必要任务数据。
- MySQL 中 `flowai_db`、`industrial_db` 使用不同账户/权限；两个后端不得使用彼此数据库凭证。
- 外部模型 API 需出站网络与有效凭证；平台私有化部署不代表推理数据不出网。必须在交付说明明确数据出境/第三方 API 风险与可选本地模型适配规划。

## 2. 环境与密钥
- 提供 `.env.example`，只含变量名和安全占位值；真实 `.env`、模型 API Key、服务密钥不入 Git。
- 明确配置项：数据库连接、Redis、ChromaDB、LLM/Embedding provider、密钥引用、服务端鉴权密钥、日志级别、上传大小限制、对外域名/TLS。
- 容器健康检查分开：liveness（进程可运行）与 readiness（关键依赖可用）；依赖失败不能假报健康。

## 3. 交付步骤（每步需脚本/手册/日志证据）
1. 服务器环境预检：Docker/Compose、CPU/内存/磁盘、端口、DNS、模型 API 连通、时间同步。
2. 配置环境变量与密钥、数据目录和权限。
3. 启动 MySQL/Redis/ChromaDB，等待就绪；执行**两个服务各自**的 Alembic 迁移。
4. 启动工业业务服务、FlowAI API/worker、前端代理；逐项健康检查。
5. 初始化四类测试用户、ServiceUser 身份映射、合成客户/设备/故障/工单；数据种子可重复执行而不重复插入。
6. 上传知识文档并等待索引 READY；创建/发布 3 个 AI 应用；执行端到端验收。
7. 检查日志脱敏、权限、容器重启持久化；记录版本与交付清单。

## 4. 备份恢复（P1）
- 备份：两个 MySQL 数据库、ChromaDB 持久数据、必要的应用配置与版本信息；密钥另行安全管理，不在备份包明文传播。
- 一致性：记录备份时间点、应用版本和向量索引版本；恢复后检查文档元数据与向量索引对应关系。
- 恢复演练：隔离测试环境恢复，校验客户/设备/工单数量、工单操作历史、已发布应用、KB 检索；记录实测 RTO/RPO，**不预先承诺**生产 SLA。
- 升级：备份 -> 执行迁移 -> 健康检查 -> 回归测试；失败时根据迁移兼容性执行经验证的恢复方案，不能简单假定数据库迁移可逆。

## 5. 故障演练
| 场景 | 期望行为 | 证据 |
|---|---|---|
| 模型 API 不可用 | 对话返回明确失败/重试提示，业务写入不伪成功 | Trace + 前端错误态 |
| Industrial API 超时 | 工单状态待核实，同幂等键安全恢复 | 工单计数 + 日志 |
| 文档索引失败 | 旧 READY 索引继续服务，失败任务可诊断 | 索引版本 + 检索结果 |
| MySQL 重启 | 服务恢复后数据一致、健康状态正确 | 重启/恢复日志 |
