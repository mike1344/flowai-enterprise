# ADR-008 跨服务认证与用户上下文传播

- 状态：**Accepted**
- 日期：2026-11-01
- 决策者：产品/技术负责人（已批准）、实施代理（起草）
- 关联：`docs/04 §6`（跨服务信任与失败语义）、`docs/10 §3-1`；任务 M01-02、M04-02；配置 M00-02
- 冻结边界：本 ADR 只定"机制"，不改 `docs/06` 的角色与资源授权规则

## 1. 背景

FlowAI API 调用 Industrial API 时，必须让工业侧知道"哪个最终用户在操作"，但**工业侧不能信任客户端或模型传来的身份**（`docs/01 §5`、`docs/04 §6`）。需要一个可验证、不可伪造、短时、可审计的传播机制。

## 2. 选项

| 选项 | 做法 | 评价 |
|---|---|---|
| A | 共享静态内部令牌 + 明文 `X-User-Id` 头 | **拒绝**：`user_id` 可被伪造，等于放弃工业侧鉴权，违反冻结的信任边界 |
| B | 内部服务凭证（签名密钥）+ **短时签名用户声明**（JWT），工业侧验签后查本地身份映射 | **采纳**：可验证、可撤销、实现成本可控 |
| C | 双向 mTLS + JWT | 安全更强，但 P0 需证书签发/轮换与宿主信任链运维，超出单机 Compose 交付范围；**保留为生产加固项**，不阻塞 P0 |

## 3. 决策

1. **令牌类型**：签名 JWT，`HS256`（预共享 32 字节随机密钥，由环境变量注入，支持 `kid` 轮换）。
   - 签发方 `iss=SERVICE_JWT_ISSUER`（默认 `flowai-api`）；受众 `aud=SERVICE_JWT_AUDIENCE`（默认 `industrial-api`）。
   - Industrial → FlowAI 的调用（如回查）使用同一机制反向签发。
2. **必需 claims**：

   | claim | 含义 | 约束 |
   |---|---|---|
   | `iss` / `aud` | 签发方 / 受众 | 必须精确匹配，校验时强制 |
   | `sub` | FlowAI 用户标识 | 不得为客户端传入值 |
   | `sid` | 会话标识 | 与消息来源会话一致 |
   | `iat` / `exp` | 签发/过期时刻 | **`exp - iat ≤ 120s`（默认 60s）**；时钟偏移容忍 ≤30s |
   | `jti` | 一次性令牌 ID | 消费记录，防重放 |
   | `act` | `{service, operation, params_digest}` | 与 ADR-009 的操作授权摘要一致 |
   | `kid`（头部） | 密钥版本 | 轮换期允许新旧并存一个有效窗口 |

3. **工业侧校验顺序（缺一不可）**：
   a. 算法白名单（拒 `none`/非对称混用）→ b. 验签 → c. `iss`/`aud`/`exp`/`iat` → d. `jti` 未消费（Redis 或表，TTL=exp）→ e. 查 `service_identity_binding`（`identity_provider='flowai'`, `external_user_id=sub`）必须 `ACTIVE` → f. 按绑定得到 `service_user_id` / `customer_id` 与 `business_role` → g. **业务资源授权再判一次**（跨客户一律拒绝，`docs/03 §1`）。
4. **禁止**：请求体或查询串传 `user_id`、`confirmed`、`customer_id` 作为授权依据；令牌放 URL；令牌写入普通日志（`docs/09 §3`）。
5. **失败语义**（`docs/04 §1/§4`）：
   - 签名失败/过期/重放 → `401 UNAUTHENTICATED`；
   - 无映射、映射 `REVOKED`、角色不符 → `403 PERMISSION_DENIED`（`IND-22`）；
   - 无法判定 `jti` 是否已用（存储不可用）→ **fail closed**，返回 `503 DEPENDENCY_UNAVAILABLE`，不得放行。
6. **密钥管理**：`SERVICE_JWT_SECRET`、`SERVICE_JWT_KID` 仅经环境变量注入；`.env` 不入 Git；轮换时保留旧 `kid` 至其 `exp` 窗口结束；密钥泄露处置为立即换 `kid` 并吊销映射。

## 4. 影响

| 面 | 影响 |
|---|---|
| API | 工业侧统一鉴权依赖；错误码沿用 `docs/04 §4`，不新增协议字段 |
| 数据 | `service_identity_binding`（`docs/03 §1`）为唯一身份映射来源；新增 `jti` 消费记录（Redis 优先，P0 可落表） |
| 安全 | 消除"裸传 user_id"路径；撤销映射即时生效（`IND-22`） |
| 测试 | 必须覆盖：无令牌、错签名、过期、重放、映射撤销、跨客户、存储不可用 fail-closed |
| 任务 | M00-02 预留中间件与配置项；M01-02 实现映射与校验；M04-02 连接器签发与传播 |

## 5. 复审条件

- 引入 mTLS 或多实例部署需要共享 `jti` 存储时；
- 需要在工业侧独立签发面向 FlowAI 的令牌（双向）时；
- `docs/10 §3-1` 若被新的安全要求取代，另开 ADR Superseded。
