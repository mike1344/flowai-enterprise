# ADR-014 索引/文档删除的清理策略与会话版本绑定

- 状态：**Proposed**（M02-03 / M03-02 开工前需批准）
- 日期：2026-11-01
- 关联：`docs/03 §6`、`docs/05 §1/§2`、`docs/10 §3-7`；任务 M02-03、M03-02、M07-01、M07-02
- 冻结边界：P0 只需"最新 READY 索引安全切换"；索引历史回滚属 P1（`docs/03 §6`），本 ADR 不提前实现 P1

## 1. 问题

共享知识库被多个应用绑定（`docs/05 §2`），删除文档/知识库/索引时若立即物理删除向量，会破坏仍在使用旧索引的应用检索，也违反"构建中的新索引不能覆盖旧索引"（`docs/05 §2`）。同时需要明确"会话绑定应用版本"的具体绑定点。

## 2. 删除与清理策略

| 对象 | 删除语义 | 前置校验 | 清理时机 |
|---|---|---|---|
| 文档（Document） | **软删除**（`deleted_at`），立即从"可见范围"移除 | 无语义依赖 | 向量清理延迟 24 小时（可配置），期间旧 READY 索引仍可服务其他文档 |
| 文档版本 / 分块 | 随文档软删除；硬删除仅在引用计数=0 时 | 引用计数=0 | 延迟任务 |
| 知识库（KnowledgeBase） | 软删除 | **必须无应用绑定**，否则 `409` | 其索引版本全部标记 `DEPRECATED` 后延迟清理 |
| 应用（AIApplication） | 停用（`DISABLED`），不物理删除 | 存在历史会话时保留元数据 | 会话按版本快照保留 |
| 索引版本（IndexVersion） | `DEPRECATED` 而非删除 | 不得删除 `active` 版本 | 保留最近 N(=3) 个就绪版本后延迟清理（P1 才做可视回滚） |

**硬规则**：
- 查询入口只允许 `active = true AND status = 'READY'` 的索引版本；
- 新索引构建失败（`FAILED`）**不得**影响旧 `READY` 版本（`docs/05 §2`、`M03-02` 验收）；
- 共享引用保护：KB 被多应用绑定时，删除/重建索引不得直接复用同一 collection 名字，必须新版本号。

## 3. 会话版本绑定

1. `conversation` 记录 `app_version_id`（发布快照 ID）与 `app_id`，创建时写入，**全生命周期不变**。
2. 已发布应用被修改 → 产生新草稿版本；**不影响既有会话**（`docs/05 §1`）。
3. 应用被 `DISABLED`：既有会话只能读取历史，不得新建消息；新建会话拒绝（`docs/06 §1`）。
4. 应用被重新发布/回滚（P1）：新会话使用新 active 版本，旧会话继续引用其 `app_version_id`（审计可追溯）。
5. 权限仍按**当前**策略校验（`docs/02 M07-01` 验收"权限仍按当前策略校验"），不得因旧版本配置放宽授权。

## 4. 影响

| 面 | 影响 |
|---|---|
| 数据 | `Document.deleted_at`；`IndexVersion` 状态机与 `active` 标记；`Conversation.app_version_id` 非空 |
| API | 删除操作返回 202/204；被绑定的 KB 删除返回 409 |
| 测试 | 删除后检索不可见、旧索引仍服务、失败构建不影响旧版本、会话版本不漂移 |
| 任务 | M02-03（发布快照）、M03-02（索引切换）、M07-01/02（P1 回滚，仅预留语义） |

## 5. 批准后的动作

转 `Accepted`；M03-02 的迁移需按本 ADR 增加 `deleted_at` 与 `IndexVersion` 字段（P0 只做"最新 READY"切换，不做 UI 回滚）。
