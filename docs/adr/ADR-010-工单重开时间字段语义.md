# ADR-010 工单重开后的时间字段语义

- 状态：**Accepted**（2026-11-01 代理批准，随 M01-03 生效）
- 日期：2026-11-01
- 关联：`docs/03 §3`（状态机）、`docs/10 §3-3`；任务 M01-03
- 待决原因：`docs/03 §3` 要求"重开后保留既往关闭/解决操作历史，时间字段语义需在实现前用 ADR 确认"

## 1. 问题

`repair_ticket` 有 `resolved_at`、`closed_at` 两个可空时间字段（`docs/03 §1`）。状态允许
`RESOLVED → REOPENED`、`CLOSED → REOPENED`、`REOPENED → IN_PROGRESS`，因此同一工单可能多次解决/关闭。
需要回答：重开后这两个字段是**保留上一次时间**还是**清空**？

## 2. 选项

| 选项 | 语义 | 优点 | 缺点 |
|---|---|---|---|
| A | 保留最近一次值（不清空） | 可快速回答"上次何时关闭" | 用 `closed_at IS NOT NULL` 判断"当前已关闭"会**误判**；统计口径混乱 |
| B | 进入 `REOPENED` 时清空 `closed_at`（`resolved_at` 保留到再次解决） | 字段语义与"当前状态"严格对应 | 丢失"上次关闭时间"，需查操作历史 |
| C | 清空两个时间字段，历史全部依赖 `ticket_action` | 语义最干净 | 列表页展示"最近解决时间"需额外 join |

## 3. 推荐决策（B 的收紧版）

1. **`resolved_at` / `closed_at` 表示"当前生命周期内最近一次到达该状态的时间"**，不是历史集合。
2. 状态转移规则：
   - `IN_PROGRESS → RESOLVED`：必须写 `resolution`，`resolved_at = now`。
   - `RESOLVED → CLOSED`：`closed_at = now`，`resolved_at` 保持不变。
   - `→ REOPENED`：`reason` 必填；**`closed_at` 置 `NULL`**，`resolved_at` 保留最近一次解决时间。
   - `REOPENED → IN_PROGRESS`：两个时间字段不变。
   - 再次 `IN_PROGRESS → RESOLVED`：`resolved_at` **覆盖**为新时间。
3. **权威历史以 `ticket_action` 为准**：每次状态变更写一条 `STATUS_CHANGE`（含 `old_status`、`new_status`、`reason`、`trace_id`），与工单变更同事务（`docs/03 §5`）。
4. 关闭状态判定统一用 `status = 'CLOSED'`，**禁止**用 `closed_at IS NOT NULL` 判定当前是否关闭。
5. 明确禁止：`PENDING → CLOSED`（`IND-15`）、未分配进入 `IN_PROGRESS`（`IND-16`）、无 `resolution` 进入 `RESOLVED`（`IND-17`）。

## 4. 影响

| 面 | 影响 |
|---|---|
| API | `GET /tickets/{id}` 返回的两时间字段语义如上；`/tickets/{id}/actions` 为完整历史 |
| 数据 | 无需新增列；`ticket_action` 必须记录 `old_status/new_status`（`docs/03 §1` 已定义） |
| 测试 | 覆盖 `IND-15`～`IND-20`：重开后字段状态、再次解决覆盖、关闭判定不误用 `closed_at` |
| 迁移 | 无（字段不变） |
