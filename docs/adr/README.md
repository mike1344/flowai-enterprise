# ADR 索引与状态机

> 归属：M00-01。本目录承载 `docs/10 §3`「实施前需以 ADR 明确的技术细节」的落地决议。
> **重要**：ADR 只明确实现层面细节，**不改变** `docs/01–08` 中已冻结的产品范围、权限模型与业务规则。

## 状态定义

| 状态 | 含义 | 谁可以改 |
|---|---|---|
| `Proposed` | 已起草，未获批准，**不得作为实施依据** | 产品/技术负责人 |
| `Accepted` | 已批准，实施必须遵守 | 不得单方修改；变更需新 ADR 或 CR |
| `Superseded` | 被后续 ADR 取代 | 记录取代者编号 |

## 规则

1. **Proposed 不得实施**：依赖某 ADR 的任务在开工前必须先把该 ADR 变为 `Accepted`（`docs/09 §6`）。
2. **冲突处理**：若实施中发现 ADR 与冻结需求冲突，停止该任务并提 CR（`docs/10 §4`），不得静默绕过。
3. **新增编号**：从 ADR-015 起顺序分配，不得复用编号。
4. **不可变**：`Accepted` 的 ADR 正文只允许追加"修订历史"，原决策与理由保留可追溯。
