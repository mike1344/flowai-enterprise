# 故障注入演练报告（2026-11-01）

> 目标（docs/07 §2、docs/08 §5）：依赖不可用时不得伪成功；恢复后自动回到正常闭环。

## 1. 演练场景：工业服务停机

```text
1) docker stop flowai-industrial-api-1
   docker inspect → State.Running=false

2) 通过 FlowAI 发起写意图对话（device_id: 1 … 创建工单）
   结果：{"http": 200, "status": "FAILED"}
   → 明确失败，未返回工单号，未写入任何业务数据
   验证：scripts/fault_drill.py --expect failed → EXPECTATION_OK

3) docker start flowai-industrial-api-1
   12s 后 docker inspect → health=healthy
   GET /api/industrial/health → 200

4) 恢复后同一意图对话
   结果：{"http": 200, "status": "WAITING_CONFIRMATION"}
   → 设备信息、历史故障、知识库引用均正常，进入人工确认
   验证：scripts/fault_drill.py --expect confirmed → EXPECTATION_OK
```

## 2. 结论

| 断言 | 结果 |
|---|---|
| 依赖不可用时不伪成功 | **PASS**（`FAILED`，无 ticket_no） |
| 错误信息可诊断 | PASS（`无法连接工业服务：ConnectError`） |
| 恢复后服务健康 | PASS（容器 healthy，入口 200） |
| 恢复后业务闭环可用 | PASS（回到 WAITING_CONFIRMATION） |
| 前端/控制台无异常报错 | PASS（浏览器控制台无 error） |

## 3. 复跑方式

```powershell
docker stop flowai-industrial-api-1; Start-Sleep 8
python scripts/fault_drill.py --expect failed
docker start flowai-industrial-api-1; Start-Sleep 12
python scripts/fault_drill.py --expect confirmed
```
