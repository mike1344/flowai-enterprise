# 07 测试策略与验收矩阵

> 目标值为拟定验收门槛，不是实测结果。先固定数据集、硬件、模型、网络、测量方法，再运行；不得事后修改门槛以迎合结果。

## 1. 测试层级
- 单元：字段/日期/唯一约束、状态机、权限决策、重复规则、幂等摘要、RAG 引用格式。
- 集成：MySQL 事务、Alembic、Industrial API、FlowAI 连接器、Redis/Celery、ChromaDB。
- 契约：OpenAPI schema、错误码、认证头、分页、版本冲突、Trace 传递。
- E2E：Vue 应用发布、文档检索、Agent 工单、权限拒绝、故障恢复。
- 安全：越权、跨客户、提示词注入、伪造确认、密钥泄露、恶意上传。
- 部署：干净环境启动、重启持久化、备份恢复、升级与回滚。

## 2. P0 验收门槛
| ID | 用例/指标 | 必须结果 | 证据 |
|---|---|---|---|
| ACC-01 | 创建/配置/发布 ≥3 个不同 AI 应用 | 无需修改后端代码；独立 URL 与访问权限生效 | E2E 视频/截图+测试记录 |
| ACC-02 | PDF/DOCX 摄取、共享 KB | 解析/索引状态正确；多应用授权复用；未授权拒绝 | 集成测试+索引记录 |
| ACC-03 | 固定 50 题 RAG 评测 | 记录答案正确性、引用准确性、拒答表现；具体阈值 Gate C 前冻结 | 标注集+评测报告 |
| ACC-04 | 20 个 Agent 任务 | 正常路径成功率目标 ≥95%，异常路径全部安全失败 | 任务集+执行 Trace |
| ACC-05 | 预置工具 ≥5 个 | 工具 Schema、应用白名单与业务权限有效 | 工具契约测试 |
| ACC-06 | 工单正常/重复/超时/重试 | 无未经确认写入；相同幂等意图不重复创建 | DB 断言+Trace |
| ACC-07 | 至少 15 个权限安全用例 | **全部**拒绝未授权访问/写入 | 安全测试报告 |
| ACC-08 | 工单状态机/事务/乐观锁 | 非法跳转拒绝；并发只允许符合版本的更新；审计同事务 | 数据库测试 |
| ACC-09 | 普通业务 API 性能 | 在指定环境下 P95 ≤500ms（不含模型） | 负载工具报告、环境参数 |
| ACC-10 | 20 并发会话 | 无数据错乱、重复工单或未授权写入 | 并发测试记录 |
| ACC-11 | 跨服务 Trace/日志 | 请求可定位，凭证和敏感信息脱敏 | 日志样本 |
| ACC-12 | 单机 Docker Compose | 全新环境按文档部署、初始化、健康检查、核心闭环通过 | 安装记录+验收清单 |

AI 首个可见响应建议目标 P95 ≤5 秒，但必须区分平台排队时间与外部模型网络/推理时间，并记录提供商与网络条件；不能将其宣传为无条件 SLA。

## 3. Industrial 关键用例（全部通过）
- IND-01 客户/型号/设备唯一键与 FK；IND-02 保修日期约束；IND-03 设备客户归属校验。
- IND-04 故障可独立创建；IND-05 工单 fault_id 可空；IND-06 绑定故障必须同设备。
- IND-07 停用客户/退役设备禁止新工单；IND-08 预检重复只提示不写入；IND-09 拒绝确认不创建。
- IND-10 二次确认成功且仍需重新校验；IND-11 token 过期/参数改变/候选变化拒绝或重确认。
- IND-12 同键同请求只产生一单；IND-13 同键不同内容 409；IND-14 响应丢失后同键重试返回原工单。
- IND-15 PENDING→CLOSED 非法；IND-16 未分配不得开始；IND-17 无 resolution 不得 RESOLVED。
- IND-18 并发 version 冲突；IND-19 工单和审计同事务回滚；IND-20 关闭重开须授权和原因。
- IND-21 跨客户设备/工单拒绝；IND-22 撤销身份映射后立即拒绝；IND-23 停用 ServiceUser 不得新分配。

## 4. P1 验收
- 应用历史版本不可变，可回滚且不绕过当前权限。
- 索引最新就绪版本可安全切换，失败不破坏旧索引，可回滚。
- 执行异常恢复不会重复写业务；确认过期不自动继续。
- 内置请求量、错误率、P95、Token 用量统计口径清晰并可对照原始数据。
- 完成至少 3 类故障注入（模型失败、Industrial API 超时、索引任务失败），有定位与恢复报告。
- 备份恢复与升级验证完成，记录实际恢复时间和数据校验结果；部署/运维/PoC/解决方案/验收文档齐备。

## 5. 验收报告模板
`测试日期、提交版本、环境(CPU/内存/OS/Docker)、模型与Embedding、数据集版本、执行命令、预期、实测、PASS/FAIL、失败原因、修复提交、复测结果、证据路径、验收结论`。

## 6. Gate 判定
任何未授权写入、跨客户数据泄漏、工单重复创建、事务不一致、虚假成功报告均为阻断缺陷；即使其他功能通过，也不得宣称 Gate D 完成。
