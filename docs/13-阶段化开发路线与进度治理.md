# 阶段化开发路线与进度治理（强制执行）

> 本文档是执行约束，不是建议性的学习计划。进度看板入口：`progress/进度看板.html`；唯一跨工具进度记录：`progress/任务进度.json`。设计已冻结不代表开发完成，初始开发验收进度为 0%。

## 1. 六个顺序阶段（不得跳阶段）

| 阶段 | 任务 | 交付物 | 阶段放行条件 |
|---|---|---|---|
| S0 基础环境 | M00-01～03 | 仓库、双服务和前端骨架、双数据库、迁移、测试基础设施 | 三端可启动、独立数据库、健康检查和基础 CI 验收 |
| S1 工业业务闭环 | M01-01～05 | 工业业务实体、身份映射、工单事务、重复确认、独立 API | 工业 API 不依赖 FlowAI 独立完成业务用例；权限、幂等、审计通过 |
| S2 平台与知识库 | M02-01～03、M03-01～03 | 平台权限、模型适配、应用发布、文档摄取、RAG | 应用可发布，知识库可引用，权限与固定问答集测试通过 |
| S3 Agent 集成 | M04-01～04 | 工具白名单、业务连接器、Agent 状态机、两次确认 | 真实 API 闭环成功；未确认不可写；重试不重复创建 |
| S4 前端与 P0 交付 | M05-01～02、M06-01～03 | 管理端、应用门户、Trace、Compose、P0 验收 | 端到端、安全、并发、故障注入和干净部署全部过关 |
| S5 P1 增强与交付 | M07-01～04、M08-01～02 | 回滚、恢复、监控、备份、售前材料 | P1 验收通过，演示和交付材料与实测一致 |

**严格顺序**：S0 → S1 → S2 → S3 → S4 → S5。阶段内部按照任务编号顺序推进；如果任务的显式依赖允许并行，首版仍保持单主任务模式，避免开发漂移。任务编号与原始 `docs/02` 保持一致，不重新编号。

## 2. 单任务闭环（必须执行）

1. 从看板的“当前唯一主线”获取任务 ID；读取对应设计章节、输入、前置依赖和验收标准。
2. `READY`：确认前置依赖均为 `DONE`，列出计划修改的文件、接口、数据库变更及测试范围。
3. `DOING`：只修改当前任务相关文件；发现跨模块新需求，写入待决问题或变更记录，不临时插队开发。
4. `REVIEW`：检查接口契约、权限边界、事务、错误路径和迁移兼容性。
5. `TESTED`：运行对应自动化测试和必要的手工验证，记录实际命令、结果、日期和证据路径。
6. `DONE`：证据可核验、测试通过、文档更新、变更提交，方可计入进度并解锁下一任务。

允许 `BLOCKED` 记录阻塞，但不得绕过阻塞改做后续阶段；需先处理阻塞原因。失败的测试不允许把状态设为 `TESTED`。

## 3. 进度计算和真实性

- 总进度 = 所有已验收 `DONE` 任务的固定权重之和；P0 占总项目 80%，P1 占 20%。
- 阶段进度 = 阶段已验收任务权重 / 阶段总权重。
- `DOING`、`REVIEW`、`TESTED` 均不计入完成率；`TESTED` 只是通过测试，需复核后才 `DONE`。
- 已完成任务发生回归缺陷时，必须重新打开该任务，撤销完成状态并重新验收；下游任务应检查是否受影响。
- 进度是**验收权重**，不是耗时比例；工作量权重仅用于可视化，不代表工期预测。
- 看板的浏览器缓存不是共享事实源。每次任务变更后导出 JSON，替换仓库 `progress/任务进度.json` 并提交 Git。换工具前先导入最新文件。

## 4. 每轮执行必须输出的记录

```text
任务：Mxx-xx / 名称
状态：READY → DOING → REVIEW → TESTED → DONE（或 BLOCKED）
输入：已完成的前置任务、引用的设计文件
实施：实际改动文件及主要变更
测试：执行命令、测试数、通过数、失败数、结果路径
验收：验收条目逐项通过情况及证据路径
风险：遗留问题、阻塞和变更请求
进度：当前阶段 x/y、P0 x%、P1 x%、总体 x%
下一步：看板解锁的下一项任务 ID
```

## 5. 不允许的开发行为

- 不得因为页面更容易演示就跳过后端权限、事务或接口验收。
- 不得跨系统直接访问另一系统的数据库。
- 不得把仅有界面、占位返回或模拟成功的功能标记为完成。
- 不得以 AI 工具的聊天记录代替仓库中的交付证据。
- 不得未经审批更改冻结需求、接口契约或任务依赖。
- 不得在 S4 P0 验收通过前进入 S5 P1 开发。

## 6. 启动时的唯一下一步

初始只解锁 `M00-01`（仓库现状审计、目录规划、ADR、环境清单）。先核对当前代码资产、环境和与冻结需求的差异，不修改项目代码；经确认后进入 `M00-02`。
